# Bounded Qwen runtime v1

This LOCAL integration implements the [reviewed Qwen proposal](../qwen_report_extraction_v1/PROTOCOL.md). Actual model generation is unexecuted and permanently blocked in this published revision, including with --execute or edited policy flags. CPU demonstrations use exactly five fabricated reports and clearly marked fabricated outputs; they cannot consume competition reports.

Preserve all 203 historical analysis files. The real preparation path verifies the previous local audit receipt and copies only label-free input records, exact control/candidate prompts, pinned tokenization, split membership and an audit receipt. Never copy the audit details or historical review CSV into the prepared runner or blinded bundle. No organizer labels are read by the runtime/review path. Source CSV bytes and split are checked through the existing label-free verifier.

The pinned Qwen3-14B checkpoint, non-thinking template, BF16/SDPA/batch-one/greedy settings, 2048-token output cap, 8192-token input cap and 300-second generation limit remain unchanged. Reuse the frozen v2 offline encoder/backend/cache verifier without changing their globals. Preparation binds runtime source, candidate source, configuration, input/order and prompt hashes. Qwen EOS IDs are [151645,151643]; there is no MedGemma thought-envelope stripping or constrained decoding.

The parent dispatches control-1, candidate-1, candidate-2, control-2 with five reports each. No retry, repair, selection or overwrite is permitted. Each worker requires an inherited parent pipe/nonce and predecessor verification; direct unparented workers fail. A worker process group is killed and reaped on timeout/interruption, bounded by the smaller of the 1800-second worker limit and remaining 3600-second session limit. Those process limits do not stop provider billing; an authorized execution version must separately implement and verify provider shutdown.

Record a durable attempt-start entry before each generation, then exact raw output before parsing. Persist primary frozen v2 response and secondary frozen v1 response under identical input/output bindings for both arms. An incomplete generation stops the worker/session. Completed schema/evidence failures remain in all planned denominators without regeneration. Parent failures preserve receipts; abrupt process death may leave partial files and no child receipt. A diagnostic inspection counts durable attempts/records and flags incomplete JSONL tails, without certifying incomplete artifacts as model evidence.

Completed-session verification checks source/plan/parent/dispatch/child/artifact hashes, exact five inputs, prompts, saved token counts/caps/stopping tokens, and reparse under both unchanged policies. Real generated inputs must equal the already pinned prepared tokenization. A later GPU execution stage must validate actual CUDA loading, model cache, generation and stopping behavior; successful synthetic tests are not that validation.

The primary-parser technical gate requires all60 valid and identical condition cells across each prompt's two repeats, using condition, label, confidence, model evidence, original span/offsets, normalization method/flag and status; runtime/timestamps are excluded. Show planned/attempted/unrun counts and primary/secondary coverage separately. Technical passage never authorizes scaling or implies semantic correctness.

The completed-session review bundle uses only label-free reports and new generated results. Random codes and shuffled presentation conceal arm/repeat; operator mappings stay outside blinded/. Review all240 cells without deduplication: technically invalid cells require an explicit unreviewable disposition; valid cells require explicit semantic categories, reviewer identity and time. Blank forms never pass. The runtime cannot certify reviewer qualifications; their verification remains an operator responsibility. A synthetic completed review is a software test, not adjudication.

The review interface shows the original v1 target definitions equally for all arms, avoiding disclosure of candidate-specific clarification wording. It never reads organizer reference labels. Finalization collects semantic review with organizer comparison explicitly deferred and all organizer values null. A later separately scoped stage may perform secondary organizer comparison only after qualified first-stage review. Preserve the inherited12 unresolved review items and do not use them as blinded review input.

No training, full40 development, reused18 validation, bulk extraction or cloud spending is authorized here. The exact five real reports are prepared but not passed to a model. This milestone ends at local runner/review validation and publication, followed by external advisory code review.
