# Qwen execution proposal v1

This prospective stage preserves the complete `analysis/qwen_runtime_v1/` package and its fixed five development reports. It proposes one Qwen3-14B control/candidate ABBA run: control-1, candidate-1, candidate-2, control-2, five reports each, at most 20 generations. The exact model revision, prompts, tokenization, parsers, four-state schema and 40/18 split remain unchanged. There is no training, validation inference, full-development inference or bulk extraction.

The target is one RTX 6000 Ada with 48 GiB VRAM. The checkpoint contains 29,536,665,640 weight bytes and the earlier A100 smoke measured 27.99 GiB peak PyTorch allocation, so 48 GiB is plausible but unverified on this hardware. The pinned execution environment is Python 3.12, CUDA 12.8, PyTorch 2.8.0+cu128, and the ten package versions in `configs/requirements.txt`. Before inference, a paid-stage implementation must verify the exact GPU name, at least 36 GiB free, native BF16, CUDA/driver/package pins, SDPA execution, full pinned cache bytes, input token parity, context limits and one bounded generation. Each saved token sequence must be decoded independently with the pinned tokenizer, removing one verified terminal EOS only, preserving other special tokens and disabling cleanup; the resulting UTF-8 bytes must equal the recorded raw output. Any mismatch stops the stage.

On 2026-09-24, RunPod's official pricing page listed the RTX 6000 Ada at $0.74/hour Community Cloud and $0.84/hour Secure Cloud. This proposal uses Secure Cloud, an 80 GB container disk, no new persistent volume and no network volume. The private grant must state and match all four settings exactly. RunPod documents stopped-Pod storage at $0.20/GB-month; the proposal conservatively allocates $0.023/hour for an 80 GB disk, but the actual pod quote must be checked. At these ceilings, 60 minutes costs about $0.863 (0.84 compute + 0.023 storage); the $1.50 proposed cap leaves a buffer. The private grant binds `provider_deadline` as the hard 60-minute boundary and `watchdog_stop_at` as exactly 300 seconds earlier. The watchdog starts stop attempts at `watchdog_stop_at`, leaving the final five minutes for retries and external stopped-state verification. Its standalone limit is also 60 minutes. The public RunPod pricing page says pod rates are billed per second. Quote validity is 24 hours from 2026-09-24T12:11:07Z and expired quotes must be refreshed.

The earlier A100 Qwen results took 22.69 and 25.34 seconds per report for one five-report repeat, implying about eight minutes of generation for the planned four passes if throughput were similar. RTX 6000 Ada throughput and setup time are unmeasured, so this is a planning baseline only. The 30-minute inference deadline and 60-minute provider deadline control even if the experiment remains incomplete.

Preparation and CPU tests do not authorize charges. A future run requires a new private 0600 approval record bound to the exact runtime plan and resource-proposal hashes, current displayed rates, pod identity, exact cloud/storage configuration, hard provider deadline and earlier watchdog stop time. Any control credential requires separate current user approval if it needs new or broader access; the old account-level key was revoked and must not be reused. Before a paid start, the operator must verify read access and an accepted stop command against the exact approved pod while it is already stopped, then independently read the stopped state again. Preserve a private, secret-free receipt with the pod ID, CLI style, before/after state, stop exit code, timestamp and confirmation that the same CLI credential context was used. `stop_watchdog.py` accepts only a 0600 receipt for the same pod/style, no more than 24 hours old, where both states are EXITED or STOPPED and the stop command succeeded. It records the receipt hash with its own armed/live PID receipt. The earlier paid attempt showed two practical control constraints: SSH did not inherit `RUNPOD_POD_ID`, and the built-in pod-scoped credential could not read the target through the CLI/GraphQL preflight. A temporary account control key later passed read/stop checks against an already stopped pod, but was revoked afterward; that does not prove a live pod stop. The previous live watchdog was armed but the operator stopped the pod early, so its timed CLI stop was never exercised. A new run must explicitly set and verify `RUNPOD_POD_ID` in the watchdog shell and confirm its access matches the private stop-preflight receipt before any model load. If these checks cannot pass using currently authorized access, do not start inference.

The watchdog targets only `RUNPOD_POD_ID`, waits until `watchdog_stop_at`, then tries stop at most three times; it never waits past the stop boundary to issue its first request and never retries inference. The hard provider deadline remains the absolute 60-minute boundary. Process exit or a successful stop request is not billing confirmation; the provider state and charges must be verified independently. The public quote and this proposal are planning information, not a RunPod-enforced hard dollar cap: the external operator must verify the provider is stopped by the absolute deadline or earlier if the displayed rate or projected total exceeds the approved limit.

The earlier Qwen runner saved output token IDs but did not independently decode them during offline verification. This proposal adds a byte-exact second decode requirement using the pinned tokenizer. A real execution revision must independently decode saved IDs to both `decoded_with_special_tokens` and `raw_output`, removing exactly one verified terminal EOS only for the latter and preserving all other special tokens. Save both re-decoded forms in the receipt and reject any byte mismatch before parsing or review.

The historical restart also failed once because the requested GPU host lacked capacity. This proposal does not authorize repeated placement, substitute hardware or a replacement volume.

The quoted prices are observed prices only, never execution authorization. This gate allows no retry, another host, a deadline extension or a larger budget after failure. A later blinded review must continue to use the frozen runtime's isolated bundle, which excludes the historical Qwen review CSV and reference-bearing details.

Official provider references: [RunPod GPU pricing](https://www.runpod.io/pricing), [RTX 6000 Ada details](https://www.runpod.io/gpu-models/rtx-6000-ada), and [RunPod stop and storage guidance](https://docs.runpod.io/get-started). Previous provider access observations are recorded in [setup attempts](../report_labeling_llm_v3_execution_v1/SETUP_ATTEMPT.md) and the [stopped-pod preflight](../report_labeling_llm_v3_execution_v1/CONTROL_PREFLIGHT.md).

This package contains a proposal and CPU-verifiable safeguards only. `execution_enabled` remains false. It does not create, start, resume or stop a pod; load a model; download weights; or generate predictions.
