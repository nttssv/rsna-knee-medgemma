# Future operator checklist

This checklist is documentary only. Execution is disabled and this milestone makes no RunPod changes.

1. From the repository root, set `RUNPOD_API_KEY` to an existing **read-only** RunPod API key in your shell (never paste it into chat or save it in the repository), then run this command for the exact stopped pod and data-center ID you are checking:

   ```sh
   RUNPOD_API_KEY="$RUNPOD_API_KEY" .venv/bin/python analysis/qwen_execution_runtime_alt_v1/scripts/capacity_watch.py --region-id US-WA-1 --pod-id YOUR_EXACT_STOPPED_POD_ID
   ```

   The checker pins proposal SHA `884dc38d2004abb44c64d2363e525969bf7f7fabd35f86eb5d03144bf34e72e2`, queries only the five versioned GPU names with `secureCloud: true` and `gpuCount: 1`, and reads the exact pod. It performs no mutation, does not create a private provider observation or approval, and never prints the API key. Re-run the same command when checking again; each output includes its UTC check time. A missing/invalid key, stale proposal, API error, missing data, or resource mismatch fails closed.
2. Read each GPU row separately. `stockStatus` and `availableGpuCounts` describe aggregate Secure Cloud stock for the requested data-center ID, while `uninterruptablePrice` is compared against that GPU's own proposal ceiling. These are candidate signals only. Do not infer that the stopped pod can resume from another pod's or a region's GPU stock.
3. Read the exact-pod fields. Confirm the ID, stopped state (`EXITED`/`STOPPED`), Secure Cloud, selected allowlisted GPU, one GPU, exact region, 80 GB container disk, zero attached persistent volume, null network volume, and the machine compute price within that GPU's proposal ceiling. Check the pod and machine cost fields as reported; a stopped pod's current cost may be zero and does not replace its configured start rate. If any required field is absent or differs, treat the result as blocked. The output also reports whether the proposal quote's freshness window is current.
4. The script deliberately ends with `BLOCKED_CAPACITY_UNVERIFIED`, even when aggregate stock and stopped-pod configuration look good. RunPod's documented read-only API exposes aggregate stock (`stockStatus`, `availableGpuCounts`) and pod/machine snapshots, but exposes resume as a mutation and has no authoritative read-only `canResume` result. A UI selector or stock snapshot therefore cannot establish exact-pod resumability. Wait for a trustworthy provider read-only signal or manual provider confirmation of that exact existing pod; do not click Start to test it. No new pod, region, or GPU may be substituted.
5. Only after exact resumability is demonstrably established, refresh the proposal quote and confirm actual signed-in rates and every resource field. A fresh capacity result alone is not spending approval. Keep execution disabled and do not create a grant until the separate explicit approval is made for the exact execution-plan SHA and exact resource boundary.
6. Before any future live stage, verify the execution-plan SHA, prepared-plan SHA, prior plan SHA, alternate proposal SHA, source hashes, and CPU tests. Capture the timezone-aware provider observation within 10 minutes before the start request in a private `0600` file. Set the provider deadline no more than 60 minutes after start, with watchdog stop exactly 300 seconds earlier.
7. The already-reviewed live checklist still applies: same-pod stopped-state control preflight, arm and independently verify the exact-pod watchdog before model/cache access, check exact GPU/BF16/CUDA/Torch/packages/driver/cache/SDPA/token parity/context/EOS, run no more than the fixed 20 ABBA generations, and stop immediately on any failure. No retry, fallback, continuation, or scope expansion is allowed.

The RunPod query fields and distinction between queries and `podResume` are documented in the [Manage Pods GraphQL guide](https://github.com/runpod/docs/blob/main/sdks/graphql/manage-pods.mdx) and [GraphQL schema](https://graphql-spec.runpod.io/). The absence of a `canResume` query field is why this checklist retains the capacity-unverified state.
